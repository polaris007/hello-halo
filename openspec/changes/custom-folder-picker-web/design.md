## Context

当前 Halo 正在从 Electron 桌面应用改造为 B/S 架构的 Web 应用。在 Electron 模式下，创建空间时可以通过 `dialog.showOpenDialog()` 选择本地文件夹作为空间的工作目录（`workingDir`）。但在 B/S 模式下，浏览器无法直接访问服务端文件系统，因此文件夹选择功能被禁用。

现状：
- `src/renderer/api/index.ts` 的 `selectFolder()` 硬编码返回 `{ success: false }`
- `src/renderer/pages/HomePage.tsx` 检测到 `isWebMode` 后禁用自定义文件夹选项
- `src/server/routes/spaces.routes.ts` 的 `POST /api/v1/spaces` 不处理 `customPath` 参数
- 服务端可能运行在 Windows、Linux、Mac 上，路径格式和磁盘结构各不相同

```
当前流程（Web 模式）:
┌──────────┐    POST /api/spaces     ┌──────────┐
│ Browser  │ ───────────────────────> │ Server   │
│ (前端)   │  { name, icon }         │ (后端)   │
│          │  ← 只能用默认路径        │          │
└──────────┘                          └──────────┘

目标流程（Web 模式）:
┌──────────┐  GET /api/v1/filesystem  ┌──────────┐
│ Browser  │ ◄──────────────────────► │ Server   │
│ (前端)   │  浏览服务端目录树         │ (后端)   │
│          │                           │          │
│          │  POST /api/spaces         │          │
│          │ ───────────────────────>  │          │
│          │  { name, icon,            │          │
│          │    customPath }           │          │
└──────────┘                          └──────────┘
```

## Goals / Non-Goals

**Goals:**
- 在 B/S 模式下支持浏览服务端文件系统并选择文件夹
- 支持 Windows、Linux、Mac 三种操作系统
- 提供安全的目录浏览 API，防止路径遍历攻击
- 前端提供直观的文件夹选择器 UI，接近原生体验
- 创建空间时支持传入 `customPath` 作为空间的工作目录

**Non-Goals:**
- 不提供文件级别的浏览（只浏览目录）
- 不提供文件上传/下载功能（已有现成 API）
- 不提供目录删除/重命名等破坏性写操作（但支持新建目录）
- 不修改 Electron 模式下的现有行为（保持原生对话框）
- 不限制可浏览的路径范围（用户需要能浏览整个服务器文件系统来选择项目目录）

## Decisions

### Decision 1: 服务端目录浏览 API 设计

**选择**: 提供两个 REST API 端点：`GET /api/v1/filesystem/roots` 和 `GET /api/v1/filesystem/browse`

**理由**:
- Windows 有多个磁盘根（C:\, D:\, E:\），而 Linux/Mac 只有一个根（`/`）。需要一个 API 获取可用的根路径列表。
- 浏览 API 接受一个路径参数，返回该路径下的子目录列表。按需加载避免一次性传输过多数据。

**替代方案**:
- WebSocket 双向通信：过度设计，目录浏览是低频同步操作，REST 更简单
- 单一 API 同时返回根和子目录：增加 API 复杂度，两个 API 职责更清晰

### Decision 2: 跨平台路径处理

**选择**: 使用 Node.js 内置的 `path` 和 `os` 模块处理跨平台差异，服务端统一使用操作系统原生路径格式

**理由**:
- `path.join()`, `path.resolve()`, `path.sep` 等 API 天然处理跨平台差异
- 路径在服务端产生、服务端消费，无需转换格式
- Windows 使用 `\` 分隔符，Linux/Mac 使用 `/`，前端只需显示服务端返回的路径

**Windows 磁盘根获取方案**: 通过 `child_process` 执行 `wmic logicaldisk get name` 或读取 `fs.readdirSync` 配合字母遍历检测可用盘符

### Decision 3: 前端文件夹选择器组件

**选择**: 新建 `ServerFolderPicker` 对话框组件，在 `HomePage.tsx` 中作为模态弹窗使用

**理由**:
- 独立组件便于复用和测试
- 对话框模式与创建空间的操作流程一致（点击浏览 → 弹出选择器 → 选择后关闭）
- 组件内部管理目录树状态，对外只暴露 `onSelect(path: string)` 和 `onCancel()` 回调

**UI 设计**:
- 顶部显示当前路径（面包屑导航）
- 中间显示当前目录下的子文件夹列表（可点击进入）
- 支持返回上级目录
- 底部显示选中路径和确认/取消按钮
- Windows 下顶层显示盘符列表

### Decision 4: 安全策略

**选择**: 使用路径规范化 + 存在性检查 + 权限验证

**理由**:
- `path.resolve()` 规范化路径，防止 `../` 遍历
- `fs.existsSync()` 检查路径是否存在
- `fs.accessSync(path, fs.constants.R_OK)` 检查读取权限
- 所有文件系统 API 都需要认证（`authMiddleware`）

**不做的限制**:
- 不限制可浏览的路径白名单（用户需要浏览整个文件系统选择项目目录，与 Electron 模式行为一致）
- 不做符号链接限制（在浏览目录阶段允许跟随符号链接）

### Decision 5: 空间创建流程修改

**选择**: 修改 `spaces.routes.ts` 的 `POST /api/v1/spaces`，可选接收 `customPath` 参数

**理由**:
- 与 Electron 模式的 `createSpace` 行为保持一致：`customPath` 作为空间的 `workingDir`
- 空间数据（对话、元数据）仍然存储在 `~/.halo/users/{user_id}/spaces/{id}/`
- `customPath` 仅作为 AI Agent 的工作目录和文件浏览的根目录
- 需要验证 `customPath` 在服务端确实存在且可读

### Decision 6: 选择器内新建目录

**选择**: 在 `ServerFolderPicker` 中增加"新建文件夹"按钮，新增 `POST /api/v1/filesystem/mkdir` 端点

**理由**:
- 用户在浏览目录时可能需要在目标位置创建新项目文件夹，避免切换到终端操作再回来选择
- 只提供创建操作，不提供删除/重命名，保持最小权限原则
- 创建成功后自动刷新目录列表并选中新建文件夹，体验流畅

**UI 设计**:
- 在目录列表顶部显示"新建文件夹"按钮（仅在非根路径时显示）
- 点击后在列表顶部显示内联输入框，用户输入名称后按回车创建
- 按 Esc 或点击取消按钮取消创建

### Decision 7: 路径可编辑机制

**选择**: 在创建空间对话框中，选择自定义文件夹后显示一个可编辑的路径输入框，用户可以直接修改路径或手动输入完整路径

**理由**:
- 用户可能知道完整路径，不需要通过选择器一层层导航
- 选择器选择后可能需要微调路径（如追加子目录名）
- 路径输入框同时起到显示选中路径的作用，减少 UI 元素

**UI 设计**:
- 选择"自定义文件夹"后显示路径输入框 + 浏览按钮
- 路径输入框支持直接编辑，修改后的路径作为最终 `customPath`
- 浏览按钮打开 `ServerFolderPicker`，选择后回填路径到输入框

### Decision 8: 不存在路径的自动创建

**选择**: 当 `customPath` 指向不存在的路径时，服务端自动创建该目录（`mkdirSync({ recursive: true })`）

**理由**:
- 用户可能手动输入一个尚未创建的新项目路径，要求用户先去终端创建再回来是不好的体验
- 使用 `recursive: true` 自动创建中间目录，简化操作
- 如果创建失败（权限不足等），返回明确错误信息

**替代方案**:
- 前端提示路径不存在让用户确认是否创建：增加交互步骤，不如自动处理直接

## Risks / Trade-offs

**[安全风险] 服务端文件系统暴露** → 通过认证中间件限制只有登录用户才能访问；API 只返回目录名不返回文件内容；只暴露目录列表，不暴露文件列表。

**[性能风险] 大目录列表** → 某些目录（如 `node_modules`）可能包含大量子目录。通过 `maxItems` 参数限制返回数量（默认 200），超出时提示用户手动输入路径。

**[兼容性风险] 不同操作系统路径格式** → 前端不做路径拼接，所有路径操作在服务端完成。前端只展示服务端返回的完整路径。

**[用户体验风险] 网络延迟** → 每次进入子目录都需要一次 HTTP 请求。可通过 loading 状态指示和简单缓存（LRU）优化体验。

**[安全风险] mkdir 写操作** → 新增 `POST /api/v1/filesystem/mkdir` 允许在服务端创建目录。通过认证中间件限制只有登录用户才能调用；只允许创建目录，不允许删除/重命名；路径规范化防止注入。

**[数据一致性风险] 路径不存在时自动创建** → 用户手动输入错误路径可能导致在意外位置创建目录。风险可接受，因为创建的是空目录，用户可事后删除。
