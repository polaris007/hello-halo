## Why

当前 Halo 应用的数据存储路径硬编码为 `~/.halo/`，这在 Docker 镜像部署场景下存在以下问题：

1. **数据持久化困难**：容器重启后 `~` 目录数据丢失，需要额外的卷挂载配置
2. **路径不灵活**：无法根据部署环境灵活调整数据目录位置
3. **多实例部署受限**：同一主机部署多个实例时，数据目录冲突

为支持镜像部署和数据持久化，需要将数据存储路径从用户 home 目录迁移到应用启动目录的子目录，并支持环境变量配置。

## What Changes

- **BREAKING** 数据存储路径从 `~/.halo/` 迁移到应用启动目录下的 `data/` 子目录
- **BREAKING** 数据库文件从 `~/.halo/halo.db` 迁移到 `{data-dir}/halo.db`
- **BREAKING** 空间目录从 `~/.halo/users/{user_id}/spaces/` 迁移到 `{data-dir}/users/{user_id}/spaces/`
- 新增环境变量 `HALO_DATA_DIR` 支持自定义数据目录路径
- 新增启动参数 `--data-dir` 支持命令行指定数据目录
- 数据目录不存在时自动创建
- 更新相关配置文档和部署指南

## Capabilities

### New Capabilities

- `data-storage-config`: 数据存储路径配置能力，支持环境变量、启动参数和应用启动目录三种方式指定数据目录位置

### Modified Capabilities

- `multi-tenant`: 多租户数据隔离的空间目录路径逻辑需要适配新的数据存储路径方案

## Impact

### 受影响的代码模块

- **配置模块**：数据目录配置初始化逻辑
- **数据库模块**：数据库文件路径解析
- **空间管理模块**：空间目录路径解析
- **文件服务模块**：文件存储路径相关逻辑
- **启动入口**：启动参数和环境变量解析

### 受影响的配置

- `openspec/config.yaml` 中的数据存储描述需要更新
- 部署文档需要更新数据目录配置说明
- Docker 部署指南需要添加数据卷挂载建议

### 依赖关系

- 无外部依赖变更
- 内部模块依赖：配置模块作为基础模块被数据库、空间管理等模块依赖

### 兼容性

- **BREAKING** 现有数据需要手动迁移
- 提供迁移脚本或迁移指南
- 旧版本配置文件不再兼容
