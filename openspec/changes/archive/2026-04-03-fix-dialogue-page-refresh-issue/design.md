## Context

当前项目在对话页面刷新浏览器时会显示"未选择空间"，导致用户无法回到之前的对话，只能关闭浏览器重新打开。项目使用 React 18 + TypeScript + Zustand 作为前端技术栈，需要实现页面状态的持久化和恢复功能。

## Goals / Non-Goals

**Goals:**
- 实现基于 URL 参数的状态管理机制，不再使用 localStorage 作为回退方案
- 在浏览器刷新后从 URL 中恢复之前的对话状态
- 为空间选择页面实现独立的 URL
- 确保用户可以正常刷新页面而不丢失对话上下文
- 保持代码的可维护性和性能

**Non-Goals:**
- 不涉及后端状态管理的变更
- 不修改现有的对话功能逻辑
- 不影响其他页面的正常功能

## Decisions

### 1. 状态恢复方案

**Decision:** 实现基于 URL 参数的状态管理机制，不再使用 localStorage 作为回退方案

**Rationale:**
- URL 方案支持通过链接直接分享对话，提供更好的用户体验
- 简化实现逻辑，减少存储相关的复杂性
- 避免 localStorage 可能带来的存储限制和安全问题
- 确保状态管理的一致性和可预测性

**Alternatives Considered:**
- 结合 URL 和 localStorage 方案：增加了复杂性，且 localStorage 可能带来安全问题
- 纯 localStorage 方案：不支持对话分享，用户体验受限
- IndexedDB：过于复杂，对于当前需求来说过度设计

### 2. URL 设计

**Decision:** 
- 对话页面：使用查询参数记录空间和对话信息，格式为 `?spaceId=xxx&conversationId=yyy`
- 空间选择页面：使用独立的 URL 路径，如 `/spaces`

**Rationale:**
- 查询参数格式简单，易于解析和生成
- 支持通过 URL 直接访问特定对话
- 保持 URL 的可读性和美观性
- 与现有路由系统兼容
- 为空间选择页面提供清晰的 URL 结构

### 3. 状态恢复流程

**Decision:** 只从 URL 恢复状态，不再使用 localStorage 回退

**Rationale:**
- 确保通过分享链接访问时能正确恢复状态
- 简化实现逻辑，减少潜在的状态不一致问题
- 提供单一的状态管理来源，提高可预测性

### 4. 对话选择策略

**Decision:** 
- 当 URL 中同时包含空间和对话 ID 时，恢复到指定对话
- 当 URL 中只有空间 ID 时，创建一个新的对话
- 当用户在新对话中发送消息并获取对话 ID 后，更新 URL 带上对话 ID

**Rationale:**
- 提供清晰的用户体验，当用户进入空间时自动准备好新对话
- 确保 URL 与当前状态的一致性
- 支持浏览器的前进/后退功能

### 5. URL 更新机制

**Decision:** 
- 在对话切换时自动更新 URL 参数，保持状态与 URL 的同步
- 在新对话创建并获得 ID 后，更新 URL 带上对话 ID

**Rationale:**
- 确保用户可以随时复制当前对话的链接
- 保持 URL 与当前状态的一致性
- 支持浏览器的前进/后退功能

### 6. 边界情况处理

**Decision:** 
- 如果 URL 里没有空间、对话 ID：
  - 在用户已经登录的情况下，跳转到空间选择页面
  - 如果用户还没有登录，跳转到登录页面
- 如果 URL 中有空间 ID 但没有对话 ID：
  - 打开空间页面并展示一个新建的对话
- 如果 URL 中的空间 ID 不存在：
  - 跳转到空间选择页面
- 如果 URL 中的对话 ID 不存在：
  - 创建一个新的对话并更新 URL

**Rationale:**
- 提供清晰的用户引导，避免用户陷入无操作状态
- 确保认证状态的正确性，保护用户数据安全
- 提供合理的错误处理，增强用户体验

## Risks / Trade-offs

### 1. 状态一致性

**Risk:** 前端 URL 中的状态可能与后端实际状态不一致

**Mitigation:**
- 在恢复状态后，立即与后端进行同步，确保数据一致性
- 实现状态验证机制，在恢复状态时检查数据的有效性
- 提供手动刷新机制，允许用户强制同步状态

### 2. URL 长度

**Risk:** 如果 URL 中包含过多参数，可能会导致 URL 过长

**Mitigation:**
- 只在 URL 中存储必要的状态数据（空间 ID 和对话 ID）
- 保持 URL 的简洁性和可读性

### 3. 安全性

**Risk:** URL 中的参数可能被恶意用户利用

**Mitigation:**
- 不存储敏感信息在 URL 中
- 实现适当的错误处理，防止状态恢复失败导致的安全问题
- 在后端验证空间和对话的访问权限
