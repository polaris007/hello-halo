## Why

当前项目在对话页面刷新浏览器时会显示"未选择空间"，导致用户无法回到之前的对话，只能关闭浏览器重新打开，严重影响用户体验。需要支持浏览器刷新功能，确保刷新后能恢复到当前对话状态。

## What Changes

- 实现基于 URL 参数的状态管理机制，不再使用 localStorage 作为回退方案
- 在 URL 中记录空间和对话信息，支持通过 URL 直接访问对话
- 空间选择页面使用独立的 URL
- 在浏览器刷新后从 URL 中恢复之前的对话状态
- 实现边界情况处理：
  - 如果 URL 里没有空间、对话 id，在用户已经登录的情况下，跳转到空间选择页面
  - 如果用户还没有登录，跳转到登录页面
  - 如果只有空间 id，没有对话 id，则打开空间页面并展示一个新建的对话
  - 一旦在新对话里发送了消息，获取了对话 id，则更新 URL 带上对话 id
- 确保用户可以正常刷新页面而不丢失对话上下文

## Capabilities

### New Capabilities
- `page-state-persistence`: 实现页面状态的持久化和恢复，基于 URL 参数解析
- `url-state-management`: 实现通过 URL 管理对话状态，支持对话分享
- `space-selection-url`: 为空间选择页面实现独立的 URL

### Modified Capabilities
- `dialogue-management`: 增强对话管理功能，支持刷新后的状态恢复和新对话创建
- `router-system`: 调整路由系统，支持带参数的 URL 和空间选择页面的 URL

## Impact

- 前端代码：需要修改对话页面组件，添加 URL 参数解析和状态恢复逻辑
- 状态管理：需要修改 Zustand 存储，添加 URL 状态管理
- 路由系统：需要调整路由处理，支持带参数的 URL 和空间选择页面的 URL
- 用户体验：提升用户体验，支持对话分享和更可靠的状态恢复
